# Export_head_detection: head detection of the regenerating planarian, code, models and parameters

> **Status in the FlatMorphAI repository.** This is the internal reference documentation of the head, eyespot and
> blastema detection code (the pages *Forecast regeneration states* and *Eyespots counter*). The application
> imports it; you do not run anything here yourself. Install only the root `requirements.txt` of the repository.
> Comments and messages have since been translated into English; file names, function names and data keys are
> unchanged, because the code reads them.

	This folder is self-contained. It holds the methodology, the code, the models and the parameter files needed to, from an original planarian image and its mask, detect the eye cups (ocelli) and produce their heat map and count, detect the blastema, compute the darkness index of the two ends, detect the head by the cascade of these three indices, build the head composite and predict the regeneration state. It also holds the Mask2Former segmenter that produces the mask, with the CLAHE enhancement used for the masks of the regeneration dataset. It is written so that another program (a PySide interface, for instance) can reimplement or call every function while reading its parameters from dedicated files, and so that the blastema and state models can be replaced without touching the code.

	All the new code is in Python 3, seed 42, and requires the GPU for the models (every module prints the device at load time). CSV files use the semicolon separator. No file of the original project (FasterViT_for_Image_Classification) is modified by this export, which is an organised copy of it. The reference scripts copied from the project (training, metrics chain, composite generation, segmentation dependencies) keep their original file names and their original comments, which are in French, because they reference each other and their outputs by those names; the new modules, the parameter files and this documentation are in English.

## 2. Shared conventions

	Images are read in BGR (OpenCV) from the full-resolution original file, masks in grey levels 0 to 255 (Mask2Former) then binarised at MASK_THR = 128 and reduced to their largest connected component. A mask under MIN_MASK_AREA = 300 pixels stops the processing. All detections work on the STRAIGHTENED worm: a rotation aligning the main axis of the mask (singular value decomposition of the pixel coordinates) with the vertical, matrix M kept. The returned coordinates are in this straightened frame, and `preprocessing.to_original(x, y, M)` brings them back into the original image. End 0 is the top of the straightened worm and end 1 the bottom. The worm length (span) is the vertical extent of the straightened mask, and every fraction of `thumbnails.csv` refers to it.

	Every thumbnail is a square of side SIZE = 384 obtained by cropping a window centred on a point, zeroing the background outside the mask, padding to a square with centred black and resizing. The function is `anchor_cascade.thumbnail(rbgr, mask, cx, cy, span, fraction)`, which also returns the box (y0, x0, oy, ox, side) that puts a 384 map back into the straightened frame (`preprocessing.project_map`).

	Both U-Nets (eye cups and blastema) read four channels: R, G, B divided by 255 and a local-contrast channel z = (local mean - grey) / local std on a 21-pixel window, brought to [0, 1] by (z + 1) / 6, normalised with means (0.485, 0.456, 0.406, 0.20) and standard deviations (0.229, 0.224, 0.225, 0.15). Their architecture is `segmentation_models_pytorch.Unet(encoder_name="timm-efficientnet-b0", in_channels=4, classes=1)` followed by a sigmoid, and the checkpoint is a dict whose key `state_dict` carries the weights (any `_enc.*` keys are ignored at load time).

## 3. Parameter files

	Every file of `parameters/` has four columns: `parameter ; default_value ; corrected_value ; description`. The rule is unique: when `corrected_value` is not empty it is used, otherwise `default_value`. The default values are those in service in the project at the date of the export and must not be modified; an interface only writes the `corrected_value` column. `parameter_reader.read("eye_thresholds")` returns the dictionary of effective values, `read_table` the raw table for display, `write_correction(name, parameter, value)` writes a correction (empty string to return to the default) and `model_path(role)` resolves the path of a model from `models.csv` (relative to the export root or absolute).

	`eye_thresholds.csv` carries the two thresholds of the eye detector you asked for, plus the peak constants. `counting_threshold` (0.60) is the threshold that minimises the absolute counting error on the frozen validation split (criterion `min_count_error`, key `peak_thr_eval` of the checkpoint, ties to the highest threshold, hence the fewest false positives) and is used to COUNT the eye cups. `head_decision_threshold` (0.85) is the threshold on the maximum response of the map for the eye step of the cascade to decide the orientation (PEAK_ANCHOR, set on 2 October 2026 for orientation accuracy, hence to avoid deciding on a false positive). `position_threshold` (0.60) selects the peaks that give the head point position. `recall_099_threshold` (0.1386) is the former threshold chosen for a recall of 0.99, kept for documentation and not used by the cascade in service. Your recollection was thus right up to one nuance: the second threshold of the head chain is the orientation-decision threshold (0.85), not the recall-0.99 threshold of an earlier version.

	`thumbnails.csv` carries the thumbnail generation parameters for each use: eye cups (fraction 0.30, raw mask, background 0), blastema (fraction 0.45, mask dilated by 0.12 x length, background 0), darkness (automatic cut half-width), state composite (channel 0 whole worm, channel 1 zoom 0.30, channel 2 super-zoom 0.15 with CLAHE clip 2 tile 8, stacked channels 0, 2, 2) and full masked images (384). `clahe_segmentation.csv` carries the pre-segmentation enhancement retained for the dataset masks (CLAHE on the L channel, clip 2, tile 16, worm threshold 0.50, two passes) and the constants of the two passes. `cascade_parameters.csv` carries BLASTEMA_MARGIN, DARKNESS_GAP, N_AXIS, N_CUTS, DARK_WINDOW, the terminal band position and the mask constants.

## 4. Worm segmentation (Mask2Former, two passes, CLAHE)

	`segmentation/segment_mask.py` loads the model `model_Mask2Former_20260324_0451` through `mask2former_api.load_model_for_segmentation` and reproduces the path of `regenerate_masks_2pass`: CLAHE enhancement of the L channel when ENABLE_CLAHE, first pass on the whole image with the worm-class probability rebuilt from the logits (sum over the queries of the product of the class softmax by the mask sigmoid, threshold WORM_THRESHOLD, 0.50 being equivalent to the argmax), second pass on a zoomed crop of each component (MODEL_SIZE 320, PAD_RATIO 0.50), skeleton-guided fusion, largest connected component. The returned mask is a uint8 0/255 of the image size. The mask folder of the regeneration dataset in service is `masks_model_Mask2Former_20260324_0451_2pass_clahe_2_t16`, hence the defaults clip 2 and tile 16; the worm threshold 0.50 is to be confirmed in the notebook log if a lowered threshold had been retained. To disable the CLAHE, write `False` in `corrected_value` of ENABLE_CLAHE.

	To replace the segmenter, drop a folder `<name>/` holding `<name>_loss_best_loss.pth` and `<name>_parameters.pkl` in the same format as the current one and write its path in `models.csv` (role mask2former_segmentation). The loading rebuilds the configuration from the pkl, the expected classes are background and worm. The image processor and the base configuration are taken from Hugging Face (`facebook/mask2former-swin-tiny-ade-semantic` or the model named in the pkl) at the first load, then cached; a machine without network access needs that cache (folder `~/.cache/huggingface`) or a local copy, as for the FlatMorphAI application.

## 5. Head detection (cascade) and composite

	`head/head_detection.py` calls `anchor_cascade.anchor(rbgr, rm)`, which returns (x, y, step, confidence, end). The three steps are evaluated at both ends, from the most specific index to the most general, and each step decides when its condition is met. Step 1, eyes: thumbnails of fraction 0.30 at both ends, eye detector, condition maximum response >= head_decision_threshold (0.85), retained end = largest mass of peaks >= position_threshold, point = barycentre of the two highest peaks. Step 2, blastema: thumbnails of fraction 0.45 on the dilated mask, segmenter, soft area = sum of the probabilities brought to the straightened scale, condition relative margin |a0 - a1| / (a0 + a1) >= BLASTEMA_MARGIN (0.84), end = largest area, point = centre of the terminal band. Step 3, darkness: Otsu index of the two ends, darkest end, no threshold (DARKNESS_GAP = 0). Fallback: largest soft area, step "undetermined" (never happened on the 2705 annotated worms). Cascade accuracy: 0.9952 on 2705 worms with decidable expert annotation (eyes 1443 worms and 0 errors, blastema 1091 worms and 10 errors, darkness 171 worms and 3 errors), measured on 4 October 2026.

	The state-classifier composite is built by `head_detection.composite` identically to `regenerate_composite_final`: channel 0 whole straightened worm in grey (background 0, bounding box, square 384), channel 1 head zoom of half-side 0.30 x length around the head point, channel 2 super-zoom of half-side 0.15 x length with CLAHE (clip 2, tile 8) and background zeroed. The state model only stacks channels (0, 2, 2); channel 1 is kept for the other modes.

## 6. Eye cups: heat map and count

	`eyes/eye_detection.py` produces for each end the thumbnail, the heat map (sigmoid of the U-Net, 384 x 384 in [0, 1]), the peaks (local maxima on a window of 2 x min_peak_distance + 1 = 15 pixels, of height >= counting_threshold) and the mass of the values above the threshold. The head end is, by default, the one with the highest maximum response (deployment convention of the metrics chain), or the one of the full cascade with the `--head` option (or `use_cascade=True`). The eye count is the number of peaks of the head end, without a cap, because 1 eye cup (asymmetric or emerging) and 3 (ectopic) are legitimate counts. The heat map is also put back into the original image frame (`heatmap_original`) and the peaks are brought back there (`eyes`, triplets x, y, height). Two thresholds are to be exposed in an interface: `counting_threshold` and `head_decision_threshold` (section 3).

	The detector was trained by `training/train_eye_detector_unified_384_rgbz_hn_f030_sansrenfort.py` (notebook attached), which builds its own dataset at every run: head thumbnails of fraction 0.30 around the brightest end for the regeneration images of States 4 to 6 annotated in cyan (Gaussian heat maps of sigma 5.25 at the annotated centres), verified negatives of States 1 to 3, and thumbnails centred on the eyes of the complete worms. Frozen split `eye_detector_split_frozen_v2.csv` by worm and by year, 70 epochs, wmse loss, seed 42. The augmentation includes an eye fade (probability 0.3) whose historical version is in this script; a version calibrated on the real State 4 contrasts (fade v4) is under trial in the project and is not included here, the exported model is the one in service.

## 7. Blastema, darkness and state classification

	`blastema/blastema_detection.py` returns, for each end, the blastema probability on the fraction 0.45 thumbnail (mask dilated by 0.12 x length), the soft and binary areas (probability >= 0.5) at the straightened scale, the relative margin, the blastema end, the proportion blastema area / worm area, and the binary mask put back into the original image. The segmenter was trained by `training/train_blasteme_segmenter_384_stratifie.py` on 764 worms annotated in cyan (split `blasteme_seg_split_stratifie.csv` stratified by state and grouped by worm), validation Dice 0.866. It will be replaced: drop the new `.pth` and edit `models.csv` (role blastema_segmenter). If the checkpoint format or the input channels change, the two functions to adapt are `anchor_cascade._load` (architecture) and `anchor_cascade._chans` (channels), nothing else depends on the model.

	`darkness/darkness_index.py` returns the indices of the two ends (top, bottom order), the gap and the darkest end: width-aligned medial axis resampled to N_AXIS = 200 points, N_CUTS = 60 perpendicular cuts bounded by the mask from abscissa 0 to 0.30 from each end, grey histogram per end, Otsu threshold, index = 1 - median of the dark class / 255. No learned model.

	`stage/stage_prediction.py` loads the production classifier and predicts the decimal state (1 to 6), the class, the uncertainty standard deviation and the two auxiliary outputs from the composite and a descriptor dictionary. The 97 expected descriptors are listed in `metrics/metriques_finales_IM002_r090.csv` and in the key `metric_cols` of the checkpoint, with their normalisation (`metric_mean`, `metric_std`, `metric_median`). They are produced by the chain of `metrics/`, which works on a whole dataset (384 masked image folders, anchor table, split) and not on an isolated image, in the following order, taken from the project file LISEZMOI_cascade_ancrage: `rebuild_processed_images_full_size` (384 masked images), `head_anchor_pass` (full-resolution head anchors, `head_anchors_regeneration.csv`), `regenerate_composite_final` (composites), `precompute_regeneration_metrics_v2` (shape, texture, axis and head descriptors, table `<dataset>_<split>_regeneration_metrics.csv`), `eye_inference_and_features` (columns eye_*, first detector `models/metric_detectors/eye_unet`), `generate_composite_and_features` (pigmentation columns, table `_eyespig.csv`), `enrich_metrics_blasteme` (blast_*), `enrich_metrics_blasteme_seg` (blast_seg_*, model `metric_detectors/blastema_unet_384`), `enrich_metrics_yeux_unet_v3` (eyeun_*, eye detector in service), `enrich_metrics_pupille` (pup_*), `metric_keeplist_rebuild`. Reimplementing these descriptors image by image in an interface is the heaviest part of the integration; the scripts are their executable specification, each documenting its columns in its header. The state classifier will be replaced: drop the new `.pth` and edit `models.csv` (role stage_classifier); if it keeps the keys of the current checkpoint (`state_dict`, `backbone`, `ch_map`, `metric_cols`, `metric_mean`, `metric_std`, `metric_median`, `stage_min`, `stage_max`, `proj_metric_hid`, `drop_path`) nothing else changes, otherwise adapt the `Net` class of `stage_prediction.py`, which is a copy of the one in `training/train_modele_production_stade.py`.

## 8. Integration in an interface (PySide or other)

	The functions to call, in the order of an analysis, are `segment_mask.Segmenter().segment(bgr)` (or an existing mask), `head_detection.detect_head(bgr, mask)`, then on the straightened image it returns `eye_detection.eye_maps`, `blastema_detection.blastema_maps` and `darkness_index.darkness_indices`, and finally `stage_prediction.StageClassifier().predict(composite, metrics)`. `single_image_pipeline.analyse` chains the first five and serves as a model. The models are loaded once (`anchor_cascade.load_models` caches the two U-Nets). The settings an interface may expose are the `corrected_value` columns of `eye_thresholds.csv` (counting threshold and head decision threshold), `clahe_segmentation.csv` (enable, clip, tile, worm threshold), `thumbnails.csv` (fractions and CLAHE of the composite) and `models.csv` (paths of the models to replace). Architecture constants (channels, normalisation, size 384) are not settings and appear in no editable file, because they are tied to the trained weights.

	For the future replacement of the models: blastema and state are the two roles expected to change, each with a single line to edit in `models.csv` and a single class to adapt if the format changes (section 7). A new eye detector would follow the same path (role eye_detector) and should provide its two thresholds, to be written in `eye_thresholds.csv`, the training script writing them into the checkpoint under the keys `peak_thr_eval` and `peak_thr_cascade`. Any change of threshold or model must be revalidated on the frozen split of the project before being put in service.

## 9. Reference performances (at the date of the export, 7 October 2026)

	Head cascade: 0.9952 on 2705 worms (section 5). Eye detector in service (checkpoint of 19 September 2026), threshold sweep on the frozen validation split with faded eyes included: at the counting threshold 0.60, recall 0.931, precision 0.968, F1 0.949, specificity on the negatives 0.955, mean absolute counting error 0.135 (key `peak_thr_sweep` of the checkpoint). A retraining of the same recipe for the fade trials (`eye_unet_cmp_fondu_historique`, 29 September 2026) gives on the real images of the frozen test split (437 thumbnails, 381 worms) a counting error of 0.0801, a State 4 eye recall of 0.806 (87 of 108) and a specificity on the State 3 heads of 0.793 (23 of 29), with a training-to-training variability of about 0.01 on the counting error. Blastema segmenter: validation Dice 0.866. State classifier, worm-grouped cross-validation of arm 5: exact accuracy 0.7354, balanced accuracy 0.7053, tolerance plus or minus 0.5 state 0.817. Mask2Former segmenter: Dice, boundary F1 and mIoU curves attached in the model folder.
