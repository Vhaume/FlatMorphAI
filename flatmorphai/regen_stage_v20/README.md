# Export_regeneration_stage_v19: regeneration state of the planarian, from the photograph to the state

> **Status in the FlatMorphAI repository.** This is the internal reference documentation of the regeneration-state
> chain (the page *Forecast regeneration states*). The application drives it through
> `flatmorphai/workers/regen_stage_v20_pipeline.py`; you do not run anything here yourself. Install only the root
> `requirements.txt` of the repository. Comments and messages of `production/` have since been translated into
> English; file names, function names and data keys are unchanged, because the chain reads them. `test_data/`
> and the checkpoints are not in the repository (the checkpoints are downloaded by `scripts/download_models.py`).

	This folder is self-contained. From an original planarian photograph it segments the worm (Mask2Former, two passes, CLAHE, choice of the worm by its shape), refines the mask with the blastema segmenter (smoothing, convex hull, opening), corrects the worm axis (skeleton, skan graph, Dijkstra, angular prolongation), detects the head with the cascade blastema, tip correction by the border radius, eyespots and darkness, builds the three-channel composite, computes the 128 morphometric descriptors (86 read by the model) and predicts the regeneration state with the two-branch classifier (ConvNeXt V2 image branch, metric branch). It is the chain in service on 19 October 2026 (version v19), the one that produced the results of the thesis (cascade 0.9950, state exact accuracy 0.744 on the frozen test split).

	The code of every method is the production code itself. The folder `production/` holds verbatim copies of the production programs (French comments and names, unchanged), and the package `regen_pipeline/` executes their functions without retyping them: the libraries (`ancrage_cascade.py`, `ancrage_cascade_v3c12_rayon_blasteme_v5s1neg_s070.py`, `cadrage_squelette_skan2.py`, `axe_largeur.py`) are imported, the functions of the dataset programs (segmentation, refinement, composite, descriptors, state network) are read from their source between two fixed markers and executed, the same mechanism as `enrich_metrics_v19.py`. The thresholds are read from the files of `parameters/` and written on the module attributes. A program that reads this README can therefore install the folder, run it on new images and check it against the production outputs stored in `test_data/`.

	No file of the original project (FasterViT_for_Image_Classification) and no file of the previous export `Export_head_detection` (7 October 2026, head detection only) is modified. The stereotypy programs are not touched. All new code is in Python 3, seed 42, CSV files use the semicolon separator, and every module stops if no GPU is visible (CUDA or ROCm) unless the variable `REGEN_ALLOW_CPU=1` is set for a slow check.

## 1. Local installation (step by step)

	1. Copy the whole folder `Export_regeneration_stage_v19/` (about 1.3 GB with the models) to the target machine. Paths inside are relative to the folder, nothing refers to the original project.
	2. Create a Python 3.12 environment (conda or venv). Install PyTorch FIRST with the command given on pytorch.org for the GPU of the machine: ROCm build for AMD (reference machine: Radeon RX 7900 XT, conda environment `Rocm_Python-3.12` under WSL), CUDA build for NVIDIA. Check: `python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"` must print True and the card name (ROCm also answers through `torch.cuda`).
	3. `pip install -r requirements.txt` from the folder.
	4. Mask2Former needs the configuration and the image processor of its base model in the Hugging Face cache (a few kB, never the weights). If the machine already ran the FlatMorphAI segmentation it already has them. Otherwise run once, with internet: `python segmentation/prepare_hf_cache.py`. It fills `models/hf_cache/`, which `regen_pipeline` then uses offline. Without this cache the loader stops (configuration) or builds a default processor by hand, which may change the masks.
	5. Check the installation: `python test_export.py` (levels 1 to 4, 6r and 6, about 2 minutes on GPU), then `python test_export.py --segmentation` (adds Mask2Former, level 5). The last line must read `EXPORT VALIDATED` (section 9). The notebook `test_export.ipynb` runs the same check cell by cell.
	6. Run on new images: `python run_pipeline.py <image or folder> --out <results folder>` (section 8).

## 4. The chain, step by step

	Conventions. Images are read in BGR (OpenCV). Masks are grey images 0 to 255, binarised at 128 and reduced to their largest connected component (`CS.masque_ver`). A worm under 300 pixels stops the processing. Points are written (y, x) in the cascade and (x, y) in the OpenCV matrices. L is the length of the worm axis in pixels, every fraction of the thumbnails refers to it. Every thumbnail is a square of 384 pixels cut by an affine transform centred 0.12 L from the tip along the axis, tip up (`CS.affine`), background outside the worm (or the dilated worm) set to 0. The two U-Nets read four channels: R, G, B divided by 255 and a local contrast channel z = (local mean minus grey) / local standard deviation on a 21-pixel window, brought to [0, 1] by (z + 1) / 6, normalised with means (0.485, 0.456, 0.406, 0.20) and standard deviations (0.229, 0.224, 0.225, 0.15), architecture `segmentation_models_pytorch.Unet(encoder_name="timm-efficientnet-b0", in_channels=4, classes=1)` followed by a sigmoid.

	Production file format. In production each step wrote its mask as a JPEG file read by the next one: Mask2Former masks by PIL (quality 75, after scaling to 255), refined masks by `cv2.imwrite` quality 100. The export reproduces this round trip in memory (`JPEG_ROUNDTRIP = True` in `segmentation.csv` and `refinement.csv`), which gives byte-identical masks (checked on the 14 test images: maximum grey difference 0 when the binary masks agree). The files written by `run_pipeline.py` are PNG, lossless, so a mask written by the export and read back gives exactly what the next step used.

### Step 1. Segmentation (Mask2Former, `segmentation.py`)

	Model `model_Mask2Former_20260324_0451` (Swin backbone, fine-tuned on the FlatMorphAI worm masks). Enhancement `clahe_2_t16`: CLAHE on the L channel of Lab, clip limit 2, tiles 16 x 16. First pass on the whole image: the worm probability is rebuilt from the logits as the sum over the queries of softmax(class) times sigmoid(mask), normalised over the classes, threshold `WORM_THR = 0.50` (equivalent to the argmax). Second pass on a crop of each component (side `MODEL_SIZE = 320`, margin `PAD_RATIO = 0.50`, components of at least `MIN_COMP = 10` pixels), fusion of the two passes guided by the skeleton (`skeleton_guided`, `BND_DIL = 0.02`, `MERGE_DIL_F = 0.05`). Choice of the worm (`choisir_ver`): candidates of area at least `AIRE_MIN = 300` pixels and at least `REL_MIN = 0.10` times the largest component, the object of largest circularity C = 4 pi A / P^2 (A area, P perimeter of the outer contour) among the objects not cut by the image frame is kept. The contrast K (median grey of the object minus median grey of a ring of 0.15 sqrt(A) around it) is only a control: when the most circular object is not the darkest one, the record carries `a_verifier = 1` and `rapport_circ` (circularity ratio), and the image should be checked visually. This rule replaced the largest component on 11 October 2026, the well-wall reflection being sometimes larger than the worm (6 masks without worm out of 3225 annotated images before the change).

	Channel order. The production program passes the BGR array of `cv2.imdecode` unchanged to the processor, which treats it as RGB. The dataset masks, hence every model downstream, were made this way, and `CHANNEL_ORDER = BGR` reproduces them. `RGB` is offered only for a future recalibration, it is not validated.

### Step 2. Refinement of the mask by the blastema (`refinement.py`)

	Mask2Former often misses the translucent blastema, which is the main state marker of early regeneration. The refinement only adds pixels, never removes any Mask2Former pixel. At each end of the worm axis (step 3 axis), thumbnail of side 0.90 L inside the worm dilated by `DIL_BL = 0.30 L` (band stored in the model under the key `dil`), blastema U-Net `blasteme_unet_384_v5_s1neg`. In the thumbnail the blastema is p >= `SEUIL_P = 0.70`, blurred (Gaussian, `SIGMA_VIGNETTE = 2` pixels) and re-thresholded at 0.5, then back-projected into the image (maximum of the two ends). Candidate pixels inside the band and outside the worm, components touching the worm kept, holes filled, contact rule: an added piece is kept if (pixels touching the mask) / sqrt(area) >= `SEUIL_CONTACT = 2.5`. Smoothing of the final mask in the added zone only (Gaussian sigma `SIGMA_IMAGE = 0.01 L`, threshold 0.5). Convex hull of each added piece restricted to the band and to the pixels where the blastema probability is at least `SEUIL_GARDE = 0.10`. Opening of the added blastema by a disc of radius `RAYON_OUV = 0.03 L`, which removes structures narrower than 0.06 L (translucent filaments, blurred debris) and keeps the blastema cap. Pre-registered evaluation on images annotated by the expert (confirmation sample, 54 images of 24 worms): blastema IoU +0.0345 [+0.0179, +0.0535] against the previous version, overflow -0.0034, inclusion +0.0047 (worm bootstrap, 2000 draws).

	Expert annotation. When an annotated copy of the photograph is given (blastema drawn in cyan, folder `--annotations` of `run_pipeline.py`), the cyan pixels absent from the original (opening 3 x 3, at least `MIN_ANNOT = 150` pixels) replace the model output: final mask = worm mask + annotated components of at least `MIN_COMP_ANNOT = 30` pixels touching it (rule "annotation alone", used in production for the images annotated in `cyan_blasteme`).

### Step 3. Worm axis, correction of the skeleton (`cadrage_squelette_skan2`, `head_cascade.py`)

	The axis is the longest path of the morphological skeleton of the mask, without pruning: skeleton by `skimage.morphology.skeletonize`, graph of the skeleton by skan, distances between end points by `scipy.sparse.csgraph.dijkstra`, longest path kept. Each end of the path is prolonged up to the contour of the mask along the direction of its last pixels (angle of the path itself, no global principal line, which failed on curved worms). The path is smoothed and resampled to `N_AXE = 200` points (`axe_largeur.lisser`), its length is L. A compact worm without usable skeleton falls back on its principal axis. The two ends give the tip and the thumbnail centre at `POS_CENTRE = 0.12 L` from the tip. The skan version of the axis was adopted on 17 October 2026 (`test_ancrage_cascade_skan2_v5s1neg_s070`, verdict RETENUE).

### Step 4. Head detection, cascade v3c12 with tip correction by the border radius (`head_cascade.py`)

	Blastema object. At each end, thumbnail of side 0.90 L (band 0.30 L), blastema U-Net, objects p >= `SEUIL_BL = 0.70` of at least `A_MIN = 30` thumbnail pixels. The object kept (`objet_blasteme`, rule v3c8 of 19 October 2026) is the ADMITTED object closest to the tip, admitted when its extent at p >= 0.50 contains the tip or when one of its pixels is at most `CONTACT_PX = 10` pixels from the worm contour. Objects inside the worm, far from the contour and without the tip (halo, translucent zone), are rejected. One candidate end per blastema, plus the opposite end when a single blastema is seen.

	Tip correction by the border radius (method of Valentin, cascade v3c12 of 19 October 2026). When the tip of the end nearest to a blastema is not inside the blastema object (pixel of the tip read in the connected component labels), the point of the axis from which the correction starts is selected on the half of the axis on the tip side. At each point P(i), the border radius r(i) is the distance from P(i) to the nearest worm border, read on the distance transform of the worm mask (cv2.distanceTransform, DIST_L2, mask 5, Borgefors 1986). The circle of centre P(i) and radius r(i) is the largest disc inscribed in the worm at that point, as in the medial axis of Blum (1967). P(i) is in connection with the blastema zone when g(i) <= r(i), g(i) being the distance from P(i) to the blastema object (same transform on the complement of the object). Among the points in connection, the point kept is the farthest from the blastema centre (numpy.argmax). No threshold is used, and the rule depends only on distances to the worm border and to the blastema, not on the local direction of the axis, so that axis undulations do not change it. When no point is in connection, the point where r(i) - g(i) is largest is kept (counted in `A3b._TRACE["n_repli"]`). The corrected tip is the last worm pixel (blastema included) on the half line from the selected point through the blastema centre, and the thumbnail centre is moved back by 0.12 L along it.

	Decision. Eyes: eye U-Net `eye_unet_cmp_fondu_poisson_v5_jeu3E` on a thumbnail of side 0.60 L (`F_EYE = 0.30`) at each candidate. The eye step decides when a maximum response reaches `PEAK_ANCRAGE = 0.85`: among the candidates carrying a blastema (`YEUX_SUR_BLASTEME`), the one with the most eyes at `SEUIL_YEUX_TETE = 0.85` (local maxima at least `MINDIST = 7` pixels apart), ties broken by their mean score. Otherwise blastema: when the relative margin of the blastema areas |a0 - a1| / (a0 + a1) reaches `MARGE_BL = 0.84`, the largest blastema is the head. Otherwise darkness: grey histogram of `NB_COUPES = 60` perpendicular cuts over 0 to 0.30 of the axis from each end, Otsu threshold, index = 1 - median of the dark class / 255, the darkest end is the head. The returned head point is the barycentre of the two best eye peaks (>= `AC.PEAK_THR = 0.60`) when eyes are seen, otherwise the tip. The record (`HeadCascade.summary`) gives the deciding step (`yeux`, `blasteme`, `noirceur`), its confidence, the tip and centre, L, the axis nature, the number of blastemas and whether the tip was corrected (`corrigee`). Accuracy on 2777 worms with an expert head annotation: 0.9950 (14 errors) for the cascade v3c8, the cascade v3c12 being measured against it (section 10). Deciding step over the 2864 composites of the dataset: eyes 1580, blastema 1083, darkness 201.

### Step 5. Composite (`composite.py`)

	Channel 0, whole worm: grey image rotated so that the principal axis of the mask (singular value decomposition of the pixel coordinates) is vertical, turned by 180 degrees when the retained tip falls in the lower half (head always up), background 0, bounding box, padded to a square, 384 x 384. Channel 1, zoom: thumbnail of half-side `FRAC_Z1 = 0.30 L` around the tip and centre of the cascade, grey, background 0 (kept in the file, not read by the model). Channel 2, super-zoom: same framing, half-side `FRAC_SZ = 0.15 L`, CLAHE clip 2 tiles 8 x 8, background 0. The composite is written as PNG, channel k of `cv2.merge` in plane k of the file.

### Step 6. Descriptors (`descriptors.py`)

	The 128 descriptors of `parameters/descriptor_columns.csv` are computed by the code of `production/enrich_metrics_v19.py` on the refined mask, with the head of the cascade (tip, centre, L rounded to 0.1 pixel as in the production journal), the blastema U-Net on the thumbnail of side 0.90 L with the object rule of `objet_blasteme` (unchanged since v3c8) at threshold 0.70, and the eye U-Net on the thumbnail of side 0.60 L with the counting threshold `THR_EYE = 0.61` and peaks 7 pixels apart. Families: shape `shp` (11, area fraction, solidity, circularity, extent, aspect, perimeter, elongation, eccentricity, Hu moments), pigmentation `pig` (8) and head pigmentation profile `pigp` (13), texture `tex` (9), ends `end` (5), light cap and CLAHE `cl` and `clh` (10 + 10), eye rings `eye` (19) and eye surroundings `eyeb` (5), blastema without network and segmented blastema `blast` (22, among which `blast_seg_prop`, blastema area over worm area, the most informative descriptor), local colour `loc` (2), eye detector scores `eyeun` (7), eyespot maturation `pup` (7, radial profile of the eyespot). The 86 read by the model were selected on the training table by mutual information with the six states >= 0.02 (k-nearest-neighbour estimator, k = 3, seed 42) then single-linkage grouping of the descriptors with |Pearson r| >= 0.90, the most informative of each group being kept. `blast_seg_prop_yr` (normalisation by acquisition year) needs the statistics of the training table and is returned empty, it is not among the 86. Five `eyeun` descriptors are empty when no eye peak reaches the threshold, as in production, and are replaced by the training median at prediction.

### Step 7. State classifier (`stage.py`)

	Two branches. Image branch: spatial transformer (initialised to the identity) on the composite channels (0, 2, 2) (whole worm, super-zoom, super-zoom), backbone `convnextv2_base.fcmae_ft_in22k_in1k_384` (timm, drop path 0.1, global average pooling), LayerNorm. Metric branch: one learned gate per descriptor, then 86 -> 128 -> 128 (BatchNorm, ReLU, dropout 0.3). The concatenation feeds the state head (64 then 1, sigmoid rescaled to [1, 6], decimal state P), the log variance head (aleatoric uncertainty, sigma = exp(logvar / 2)), and auxiliary heads of each branch (returned as `stage_image_branch` and `stage_metric_branch`). The image is scaled to [0, 1] and normalised by the timm mean and standard deviation of the backbone. The descriptors are completed by `metric_median` and standardised by `metric_mean` and `metric_std`, the three vectors being stored in the checkpoint with `metric_cols`. Class = clip(floor(P + 0.5), 1, 6) (`CLASS_RULE = floor_half`, rule of `evaluation_pli_test_stade_v19`). Training: target the decimal state annotated by the expert, loss = Gaussian negative log-likelihood of the main head (mean and log variance) + 0.3 Huber loss of each auxiliary head + 0.001 L1 penalty of the gate, AdamW with a lower rate on the backbone, 3 warm-up epochs then cosine decay, 30 epochs, augmentation by horizontal and vertical flips and rotations by 90, 180 or 270 degrees (probability 0.5 each), seed 42, on all 2196 images of `dataset_dedup_State_50valid_30test` with composites `processed_composite_384_uni_final_v18`.

## 5. Parameter files

	Every file of `parameters/` has four columns `parameter`, `default_value`, `corrected_value`, `description`, semicolon separated. Single rule: when `corrected_value` is not empty it is used, otherwise `default_value`. The default values are those of production on 19 October 2026 and must not be edited, an interface writes only `corrected_value` (`parameter_reader.write_correction(file, parameter, value)`, empty value to return to the default). In `cascade.csv`, the prefix `A3b.` targets the module `ancrage_cascade_v3c12_rayon_blasteme_v5s1neg_s070` and `AC.` the module `ancrage_cascade`. Some values are tied to the trained weights and are listed for documentation only: thumbnail side `S = 384`, fractions `FRAC = 0.45` (blastema) and `F_EYE = 0.30` (eyes), `DIL_BL = 0.30` (checked against the key `dil` of the blastema model), composite `SIZE = 384`. Any change of another threshold must be revalidated (section 9 and the evaluation programs of section 11).

A U-Net checkpoint must keep the format `{"state_dict": ..., "dil": ...}` (blastema) of the current ones, otherwise adapt `ancrage_cascade._charge` (architecture) and `_chans` (inputs) in a new copy. A state checkpoint must keep the keys `state_dict`, `backbone`, `image_size`, `ch_map`, `metric_cols`, `metric_dim`, `metric_mean`, `metric_std`, `metric_median`, `stage_min`, `stage_max`, `proj_metric_hid`, `drop_path`. If its descriptor list changes, the descriptors are taken by name from the 128 computed, nothing else changes. Revalidate with the programs of section 11 before use.

## 12. Known limits

	The worm choice by circularity has been checked on the 38 images with several candidates of the dataset and on 10 marked images, a disagreement with the contrast is flagged (`a_verifier`) and should be looked at. The eye descriptors are unstable on faint eyes (section 9), which mainly affects States 3 to 5. The skeleton end can move with a few pixels of blastema on a short worm. The darkness step decides without threshold (201 worms of the dataset, the weakest step of the cascade). The state classifier is weakest on State 5 (recall 0.409), mostly confused with State 4 and 6. Mask2Former reads the BGR array (section 4), changing this requires recomputing the whole chain.
